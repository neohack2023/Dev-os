# STONE Intake Contract

STONE is the source boundary and evidence gate for material that may become durable project knowledge. It is not required for every transient code edit.

A STONE package must make the source identity, episode boundary, requested transformation, resolved scope, included/excluded artifacts, retained/rejected receipts, duplicate/conflict candidates, uncertainty, provenance, and integrity explicit.

Retain user decisions, accepted artifacts, observed test/runtime evidence, durable constraints, reusable methods, failures that change future work, unresolved blockers, evidence pointers, and authority/lifecycle decisions.

Reject conversational glue, duplicate explanation, unsupported certainty, hidden reasoning, sibling-project material outside the boundary, abandoned drafts without reusable lessons, and speculative associations presented as fact.

Frequency is evidence about prevalence, not authority. If source/boundary/provenance/conflicts are unresolved, STONE stays unlocked and MASON must not silently import extra context to repair it.
