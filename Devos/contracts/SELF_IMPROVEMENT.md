# Self-Improvement Contract

DevOS may learn from observable failures and recurring friction, but it cannot grant itself new authority.

Loop: observed event → structured system feedback → independent recurrence or strong verifier evidence → STONE candidate → MASON classification → reviewed repository change → regression evidence → optional upstream sync.

Candidates must identify the failure, affected surface, evidence, proposed smallest rule/tool/test change, expected benefit, regression risk, and a cheap falsification test.

Repetition never self-promotes. A model suggestion remains a suggestion. Accepted code/tests may strengthen repository-local authority only inside their authority domain.
